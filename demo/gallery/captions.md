# Gallery captions

Burned into each plate already; here as text for Devpost's own caption field, and so that the order is written down somewhere. 13 to 15 come from [diagrams.html](../diagrams.html), screenshotted at 1600x1067.

01. **THE PLAN** — Fourteen courses, put there by hand. Term 3 has six credits left, and the page has registered its thirteen tools with the browser.

02. **THE QUESTION** — The student asks in their own words, naming no tool: what are my options, and what does each one cost?

03. **compare_options** — Both futures in one call. Either choice closes a specialisation — the slot is what costs, not the course.

04. **protect_track** — The student draws a line. Anything that would close Graphics is refused from now on, including if they ask for it themselves.

05. **THE LIMIT, ON THE PLAN** — A lock beside the track, and a line naming who it binds. Every other rule here belongs to the university. This one belongs to the student.

06. **REFUSED** — The agent asks for NUM-201. The page refuses, citing the student's own instruction, and names both ways out.

07. **WHAT THE ASSISTANT SAW** — The refusal comes back as prose, so the agent reports it rather than retrying. Nothing instructed it to.

08. **REWIND** — Every call is an event and the plan is their reduction, so undo is replaying fewer of them. The protection unwinds with the rest.

09. **THIRTEEN TOOLS** — Each description says when to reach for it. That string is the only thing a model has to choose on, so the strings are the product.

10. **REGISTRATION** — registerAll, on document.modelContext. No build step, no dependencies, no server: what is in the repository is what is served.

11. **WHO CALLED** — The page counts calls by origin and states plainly that it cannot verify the second number. WebMCP gives the handler no caller identity.

12. **LIVE** — Apache-2.0, thirteen tools on document.modelContext, and no server behind any of it.

13. **THE MODULES** — Eleven files, no build step and no dependencies. Every import points downward, which is the whole reason the layering is worth drawing.

14. **THE ONE DECISION** — Every tool call is an event, and the plan is the reduction of the events. Refusing, undoing and auditing all fall out of that; none of them was built.

15. **WHERE IT WAS TESTED** — Both of the environments named in the challenge rules, and both make real tool calls. What separates them is what a page can tell you when they do not.
