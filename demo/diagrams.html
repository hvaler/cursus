THE ONE DECISION
Every tool call is an event, and the plan is the reduction of the events. Refusing, undoing and auditing all fall out of that; none of them was built.
a tool call
↓
the rules accept it
↓
an event is appended to the log
↓
state = reduce(log)
the rules refuse it
↓
nothing is written
↓
a string naming the rule, the reason,
and what would unblock it
undo_to(n) is reduce(log.slice(0, n))
list_actions() is the log itself
share_plan() is the log in a link, replayed through these same rules
WHERE IT WAS TESTED
Both of the environments named in the challenge rules, and both make real tool calls. What separates them is what a page can tell you when they do not.

Chrome 149+

the WebMCP flag, and the Inspector extension
  • An agent chose the tool on its own, was refused, and proposed the fix — then asked permission before applying it. Nothing prompted that.
  • No plan, no mode, no workspace conditions.
  • Written up in docs/GATE.md with the flag and the extension named, so somebody else can run it.

ChatGPT's in-app browser

where the video was recorded
  • The page registers, and a model calls — in Work mode.
  • Outside it, four different phrasings produced no call at all, and confident answers read off our own README instead.
  • Site tools do not exist in Enterprise or Edu workspaces. No setting brings them back, and nothing on screen says so.
The eight scored and adversarial scenarios ran in neither of them. eval.mjs imports the tools and drives them from Node, so 8/8 is a fact about the descriptions and the strings, not about a browser.

And registration succeeding is not evidence that a model can call anything. Zero calls is consistent with the host never bridging the tools, with a model declining, with no agent present, and with the client being in the wrong mode — a page sees one number for all four.
